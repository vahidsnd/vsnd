# نئون براول — سند تحویل (Handoff)

تاریخ: ۱۷ مهر ۱۴۰۵ · برنچ: `claude/platform-fighter-game-kkytad` · نسخه تست: `1.5.0-test` (versionCode 6)

این سند برای کسی است که پروژه را تحویل می‌گیرد (خودتان یا یک برنامه‌نویس دیگر): الان چه چیزی آماده است، چطور اجرا و ساخته می‌شود، و قبل از انتشار در مایکت و گوگل‌پلی دقیقاً چه کارهایی مانده است.

```

  src/services/  backend، ads، billing، platform، prefs (تنظیمات دستگاه)، social (سرور یا دنیای دموی آفلاین)
  src/ui/        progress.ts = نقشه، جادو، لیگ، صندوق پیام، گردونه، ارتقا · clan.ts · chat.ts · police.ts
  plugins/       پلاگین‌های بومی تپسل و مایکت برای Capacitor

docs/     GDD.md (سند طراحی بازی)، HANDOFF.md (همین سند)، screenshots/
```

## ۳. اجرا و تست

```bash
npm install
npm run dev          # سرور :8787 + کلاینت :5173
npm test             # ۶۵ تست (شامل تست کامل قبیله/چت/پلیس/کد تخفیف روی سرور): شبیه‌سازی، اقتصاد، سرور (صف‌یابی، تسلیم، اتاق، خرید)
npm run typecheck
```

ساخت APK تست (همان فایلی که برایتان فرستاده شد):

```bash
cd client/native-shell
ANDROID_JAR=/path/to/android-34/android.jar ./build-apk.sh
# خروجی: client/native-shell/build/NeonBrawl-test.apk
```

نیازمندی‌ها: JDK، `aapt`، `dalvik-exchange`، `zipalign`، `apksigner` (در اوبونتو با apt نصب می‌شوند).

**تست آنلاین روی گوشی:** سرور را روی یک هاست با آدرس عمومی اجرا کنید (`npm run build && npm start`)، سپس در بازی: تنظیمات ← سرور ← آدرس را وارد و ذخیره کنید.

## ۴. کارهای باقی‌مانده تا انتشار (به ترتیب)

### الف) سرور
1. یک VPS (ترجیحاً داخل ایران برای پینگ کمتر کاربران مایکت) + دامنه + HTTPS (Caddy یا nginx).
2. اجرا با `NODE_ENV=production` (خرید آزمایشی خاموش می‌شود) و یک process manager مثل pm2 یا systemd.
3. پشتیبان‌گیری روزانه از `server/data/db.json`. برای بیش از چند هزار کاربر، `server/src/db.ts` را به PostgreSQL منتقل کنید (فقط همین فایل باید عوض شود).

### ب) کلیدها و تنظیمات (فعلاً به درخواست شما کنار گذاشته شده)
| مورد | کجا گذاشته شود |
|---|---|
| آدرس سرور | `VITE_SERVER_URL` در `client/.env.myket` و `client/.env.googleplay` |
| کلید و Zoneهای تپسل | `client/.env.myket` |
| کلید RSA پرداخت مایکت | `client/.env.myket` |
| توکن API توسعه‌دهنده مایکت | متغیر محیطی سرور `MYKET_ACCESS_TOKEN` |
| App ID و Unitهای ادموب | `client/capacitor.config.ts` و `client/.env.googleplay` (الان شناسه‌های تستی گوگل هستند) |
| Service Account گوگل‌پلی | متغیر محیطی سرور `GP_SERVICE_ACCOUNT` |
| پیامک ورود (کاوه‌نگار) | `KAVENEGAR_API_KEY` و `KAVENEGAR_TEMPLATE` |
| ورود Google Play Games | `GPG_CLIENT_ID` و `GPG_CLIENT_SECRET` |
| اعلان Push (Firebase) | `FCM_SERVICE_ACCOUNT` |
| پایگاه داده | `DATABASE_URL` (PostgreSQL) — جزئیات در `docs/DEPLOY.md` |
| پنل مدیریت | `ADMIN_KEY` (آدرس `/admin`) |

### ب۲) مدیر و پلیس بازی
* روی سرور متغیر `ADMIN_KEY` را بگذارید. سپس اولین مدیر را با شناسه بازیکن (در تنظیمات بازی نوشته شده: `ID: u_...`) بسازید:
  ```bash
  curl -X POST https://SERVER/api/admin/staff -H 'x-admin-key: ADMIN_KEY' -H 'content-type: application/json' -d '{"target":"u_xxxx","role":"admin"}'
  ```
* از آن به بعد مدیر از داخل بازی (منوی «پلیس بازی») ناظر (mod) تعیین می‌کند، گزارش‌ها را بررسی می‌کند و کد تخفیف می‌سازد. ساخت کد از ترمینال هم ممکن است:
  ```bash
  curl -X POST https://SERVER/api/admin/promo -H 'x-admin-key: ADMIN_KEY' -H 'content-type: application/json' \
    -d '{"code":"NOWRUZ1405","reward":{"gems":100,"runes":200,"fighters":["kage"]},"maxUses":5000,"days":14}'
  ```
* سایر تنظیمات سرور: `WAR_BOT_AFTER_MS` (پیش‌فرض ۵ دقیقه) و `UNLOCK_ALL=1` فقط برای تست.

### ج) بیلد فروشگاهی (روی سیستم خودتان)
```bash
cd client
npx cap add android                 # یک بار
npm run android:myket               # یا android:googleplay
npx cap open android                # ساخت AAB/APK امضاشده در Android Studio
```
* در `android/app/src/main/AndroidManifest.xml` برای Activity مقدار `android:screenOrientation="sensorLandscape"` را اضافه کنید (Capacitor این را خودش نمی‌گذارد).
* اولین بیلد ممکن است به تنظیم نسخه کتابخانه تپسل/مایکت در `client/plugins/*/android/build.gradle` نیاز داشته باشد؛ کد جاوای این دو پلاگین طبق مستندات رسمی نوشته شده ولی اینجا کامپایل نشده.
* یک keystore دائمی بسازید و نگه دارید؛ بدون آن آپدیت در مارکت ممکن نیست.

### د) کنسول مارکت‌ها
* ساخت محصولات درون‌برنامه‌ای با همان شناسه‌ها: `gems_80`, `gems_500`, `gems_1200`, `gems_2600`, `gems_7000`, `starter_pack`, `no_ads`, `season_pass`, `all_fighters`.
* سیاست حریم خصوصی (لینک لازم است)، رده سنی، و برای گوگل‌پلی فرم Data Safety و اعلام احتمال جعبه‌ها (داخل بازی نمایش داده می‌شود).

## ۵. نکات فنی مهم

* **قطعیت شبیه‌سازی:** همان کد `shared/src/sim.ts` روی سرور و گوشی اجرا می‌شود. نتیجه و جایزه مسابقه آنلاین فقط روی سرور محاسبه می‌شود.
* **شبکه:** کلاینت حرکت خودش را بلافاصله اجرا و با هر snapshot سرور (۳۰ بار در ثانیه) اصلاح می‌کند؛ اصلاح‌ها به‌صورت نرم نمایش داده می‌شوند.
* **عملکرد:** در محیط تست (بدون کارت گرافیک، ۹۱۵×۴۱۲ افقی) کیفیت «خودکار» میانگین حدود ۴۲ تا ۴۵ فریم و میانه ۶۰ فریم داشت؛ «زیاد» روی این محیط کند است و برای گوشی‌های قوی است. روی گوشی واقعی هنوز با ابزار پروفایلر اندازه‌گیری نشده است؛ اگر گوشی ضعیفی کند بود، رندرر خودکار رزولوشن را پایین می‌آورد (`noteFrame` در `renderer.ts`).
* **آفلاین:** اگر سرور در دسترس نباشد، بازی با پروفایل محلی کار می‌کند (کامپیوتر، تمرین، فروشگاه). پروفایل آفلاین با پروفایل آنلاین ادغام نمی‌شود.
* **ضد تقلب اقتصادی:** جایزه بازی‌های زیر ۲۵ ثانیه کم می‌شود؛ سقف روزانه ۴۰ بازی مقابل کامپیوتر و ۲۰ تبلیغ جایزه‌دار؛ هر توکن خرید فقط یک بار پذیرفته می‌شود.

## ۵.۱ نسخه تست (APK) بدون سرور
APK تست به هیچ سروری وصل نیست، پس بخش‌های اجتماعی در یک «دنیای دمو» روی خود گوشی اجرا می‌شوند: ۱۰ قبیله کامپیوتری با اعضا، چت زنده با ربات‌ها، جنگ ۱۵ دقیقه‌ای با رقیب کامپیوتری، و شما مدیر پلیس بازی هستید. قوانین دقیقاً همان کد سرور است (`shared/src/social.ts`).
* کدهای آماده برای تست: `NEON2026` (الماس، رون، سکه)، `VSND` (یک مبارز + کارت)، `ARCANE` (رون + جادوی شهاب).
* در تنظیمات گزینه «حالت تست: باز کردن همه قابلیت‌ها» هست تا بدون تمام کردن نقشه همه‌چیز را ببینید. روی سرور واقعی اثری ندارد.

## ۶. ریسک‌ها و موارد شناخته‌شده

1. **پلاگین‌های بومی کامپایل نشده‌اند** (تپسل، مایکت) — اولین ریسک بیلد فروشگاهی.
2. **تأیید تبلیغ جایزه‌دار سمت سرور (SSV) پیاده نشده**؛ فعلاً فقط سقف روزانه دارد. برای اقتصاد بزرگ‌تر، SSV ادموب/تپسل را اضافه کنید.
3. **ربات‌ها در صف آنلاین** بعد از ۱۵ ثانیه (عادی) و ۳۰ ثانیه (رقابتی) جای خالی را پر می‌کنند و با برچسب «ربات» نشان داده می‌شوند.
4. **صدا و موسیقی** هنوز با کد ساخته می‌شوند؛ برای انتشار بهتر است فایل‌های صوتی حرفه‌ای جایگزین شوند.
6. **ارتقای کارت و جادو در بازی آنلاین هم اثر دارد** (به درخواست شما). اثرها محدود شده‌اند (حداکثر ۲۰٪)؛ اگر خواستید لیگ «برابر» داشته باشید، در `matchmaker.ts` برای حالت ranked مقدار `mods` را خنثی کنید.
7. **دیتابیس JSON**: با قبیله‌ها و چت، برای بیش از چند هزار بازیکن هم‌زمان باید `server/src/db.ts` به PostgreSQL/Redis منتقل شود.
8. **نقشه آفلاین سمت کاربر محاسبه می‌شود** (مثل بازی با کامپیوتر)؛ کسی که کلاینت را دستکاری کند می‌تواند نقشه را زودتر باز کند. جایزه‌های نقشه محدود و یک‌باره‌اند.
5. **ریست فصل رتبه** هنگام اولین ورود هر بازیکن در فصل جدید انجام می‌شود؛ جایزه پایان فصل هنوز خودکار توزیع نمی‌شود.
